Аналіз лабораторної роботи №1
1. Мета роботи

Метою лабораторної роботи було створення базового backend-застосунку для стрімінгового сервісу з використанням FastAPI та REST API підходу.

У межах роботи було реалізовано:

CRUD операції;
JWT автентифікацію;
роботу з базою даних;
валідацію даних;
unit та integration tests.
2. Архітектура проєкту

У лабораторній роботі використовувалась відносно проста структура проєкту без чіткого розділення на архітектурні шари.

Основні компоненти:

routers;
services;
repositories;
models;
schemas;
security.

Бізнес-логіка частково знаходиться в сервісах, а частково залежить від інфраструктурних компонентів.

3. Переваги такої структури

Основною перевагою є простота реалізації. Проєкт легко запускати та розробляти, оскільки структура не містить великої кількості абстракцій.

Також:

менше boilerplate-коду;
швидше створення CRUD-функціоналу;
простіша навігація по проєкту.
4. Недоліки

Основний недолік — слабке розділення відповідальності.

Бізнес-логіка частково залежить від:

FastAPI;
ORM;
структури HTTP-запитів.

Через це:

складніше змінювати архітектуру;
важче тестувати доменну логіку окремо;
збільшується зв’язаність між компонентами.
5. Висновок

Лабораторна робота №1 стала базою для подальшого розвитку архітектури системи.

У роботі було реалізовано основний REST API функціонал та базову структуру backend-застосунку. Надалі ця структура була покращена в наступних лабораторних роботах через впровадження шарової архітектури, CQS та асинхронної взаємодії.
